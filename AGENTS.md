# AGENTS.md

Rules for any coding agent (Claude Code, Codex, Cursor, Copilot…) in this repository.
The repository is public: everything in it is in English, and no client or personal data goes in.
Architecture: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Design: [docs/DESIGN.md](docs/DESIGN.md).

## Commands

```bash
pnpm install               # install (Node 22, see .nvmrc)
pnpm dev                   # site on 127.0.0.1
pnpm storybook             # Storybook on http://127.0.0.1:6006 (docs and component stories)
pnpm --filter atlas-site share-images   # redo og.png, social-preview.png and the README cover after a copy or scoreboard change
pnpm readme                # rewrite the README scoreboard from evals/results/latest.json (run after pnpm eval)
pnpm --filter atlas-site record-demo    # redo docs/media/atlas-demo.gif, .mp4 and .en.vtt (needs ffmpeg)
pnpm check                 # types + lint + format + tests + build: required before you finish
pnpm vitest run <file>     # one test
pnpm --filter <package> build   # one package (names in docs/ARCHITECTURE.md)
pnpm e2e                   # Playwright: site, 404, Storybook and social cards (after pnpm build)
pnpm qa                    # pnpm check, then pnpm e2e: the whole suite
pnpm mcp                   # MCP server over stdio (after pnpm build); --http for HTTP
pnpm smoke                 # the built server over stdio, as Claude Code runs it
```

## What the code doesn't tell you

- The visual reference is the approved design: `docs/DESIGN.md` and the screens in Storybook. Where the
  code and an older screenshot disagree, `docs/DESIGN.md` lists the accepted differences.

- Storybook docs pages are React (`packages/ui/stories/**/…Page.tsx`) rendered through thin MDX files; the
  props, do / don't and "What the agent receives" come from the manifest and the MCP server's own code.
- `packages/ui/atlas.manifest.json` is what the MCP server knows about the components. Change a
  component, change the manifest in the same PR (`mcp/src/manifest.test.ts` checks it).
- `mcp/data/` is generated by the MCP build; don't edit or commit it.
- The site reads `evals/results/latest.json` at build time and copies `packages/ui/storybook-static` (made by the
  `atlas-ui` build) to `/storybook/`. Site colors come from tokens, except the "what the agent guessed" picture
  (`site/src/components/GuessedScreen.tsx`), which shows the model's own fixed colors on purpose.

## Rules

- Color only through tokens; components only from `@leonfpontes/atlas-ui` (why: it is the rule the
  MCP server teaches, so the repository has to follow it too).
- Never read, print or commit secrets (`.env*`, tokens). A new variable goes in `.env.example` with no value.
- No third-party brand, client or personal names in the code or docs
  (test: `tests/repo.test.ts`).
- Decisions that are hard to undo get an ADR in `docs/adr/`.

## Done means

1. `pnpm check` passes.
2. No console errors in the browser at 1440 and 375 px (when there is a UI).
3. `docs/` updated if a route, contract, command or variable changed.
4. One line in `CHANGELOG.md`.

## Traps already paid for

| Symptom                                                           | Cause                                                                                                                                                                                                                                |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm test -- --coverage` runs without coverage                   | pnpm passes the `--` on to Vitest; use `pnpm test --coverage`                                                                                                                                                                        |
| Vitest refuses to start on Node 20                                | Vitest 5 needs Node 22.12+; use `.nvmrc` (the published MCP server still runs on 20.19+)                                                                                                                                             |
| `Cannot find module '@leonfpontes/atlas-tokens'` on a clean clone | The package's `dist/` doesn't exist before the build. Workspace imports resolve to `src/` through the `atlas-source` export condition (TypeScript) and the aliases in `vitest.config.ts`; a new package the others import needs both |
